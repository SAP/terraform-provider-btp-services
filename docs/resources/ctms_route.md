# btpservice_ctms_route (Resource)

Manages a CTMS route. Requires Terraform 1.14+. Import using its decimal ID or an identity containing endpoint and id. Omitted optional settings remain managed by CTMS.

## Example Usage

```terraform
resource "btpservice_ctms_node" "source" {
  name    = "DEVELOPMENT"
  virtual = true

  lifecycle {
    create_before_destroy = true
  }
}

resource "btpservice_ctms_node" "target" {
  name    = "QUALITY"
  virtual = true

  lifecycle {
    create_before_destroy = true
  }
}

resource "btpservice_ctms_route" "development_to_quality" {
  name           = "DEVELOPMENT_TO_QUALITY"
  source_node_id = btpservice_ctms_node.source.id
  target_node_id = btpservice_ctms_node.target.id
}
```

## Replacing connected nodes

Node names require replacement when changed. Use `create_before_destroy` on both connected nodes, as shown above, and reference their IDs in the route. Terraform can then create a node with its new name, update this route in place, and delete the original node. CTMS rejects deletion of a node while any route still references it.

The replacement node name must be unique; forcing replacement with the same name can fail. Routes managed outside this Terraform configuration must be removed or rewired separately before the original node can be deleted.

## Schema

### Required

- `name` (String) Route name. Supports in-place updates.
- `source_node_id` (String) Decimal source node ID. A source can have multiple outgoing routes.
- `target_node_id` (String) Decimal target node ID. A node can be the target of only one route.

### Optional

- `description` (String) Route description, up to 512 characters. Supports Latin letters, numbers, spaces, and -._~:\/?#[]@!$&()*+,;=%. Empty descriptions are sent as JSON null. Omit to leave it managed by CTMS.

### Read-Only

- `id` (String) Decimal route ID assigned by CTMS.

## Import

Import is supported using the following syntax:

```terraform
# Use the provider configuration for the original CTMS landscape.
terraform import btpservice_ctms_route.development_to_quality "12345"
```

Alternatively, use a structured identity in an `import` block with Terraform 1.14 or later:

```terraform
import {
  to       = btpservice_ctms_route.development_to_quality
  provider = btpservice.landscape
  identity = {
    endpoint = "https://transport-service-app-backend.ts.cfapps.eu10.hana.ondemand.com"
    id       = "12345"
  }
}
```

Configure the `btpservice.landscape` provider alias with credentials for the intended CTMS landscape and set `provider = btpservice.landscape` on the destination resource block as well. Set the identity's `endpoint` to that provider's CTMS service root without `/v2` or a trailing slash.
The regional endpoint may be shared by tenants; the credentials select the landscape.
